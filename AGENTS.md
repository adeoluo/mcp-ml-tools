# AGENTS.md

Working notes for coding agents and contributors in **mcp-ml-tools**. The [README](README.md)
explains what the project does and why; this file explains how to change it safely.

## Project

A Model Context Protocol server that gives Claude Desktop, VS Code, and Cursor practical machine learning engineering tools.

## Layout

- `docs/`: documentation, architecture diagram source and render, design records
- `examples/`: runnable examples and sample configuration
- `scripts/`: maintenance scripts (release, assets, data)
- `src/`: library and service source
- `tests/`: test suite

Key modules:

- `src/cli.ts`
- `src/config.ts`
- `src/documentation.ts`
- `src/documents.ts`
- `src/errors.ts`: An error caused by invalid tool input; reported to the client as a tool error, not a crash.
- `src/http.ts`
- `src/index.ts`
- `src/metrics.ts`
- `src/prices.ts`: Default model price table.
- `src/random.ts`: Mulberry32: a small, fast, seedable 32-bit pseudo-random number generator.
- `src/server.ts`
- `src/tools/bm25.ts`
- `src/tools/bpe-corpus.ts`: Small original English and code corpus used to train the built-in byte-level BPE vocabulary.
- `src/tools/bpe-merges.ts`: Generated by scripts/train-vocabulary.mjs.
- `src/tools/bpe-settings.ts`: Number of merges learned for the built-in vocabulary (vocabulary size is 256 + merges).
- `src/tools/bpe.ts`: Byte-level byte pair encoding (BPE): a small, dependency-free implementation of the scheme used by GPT-2 style tokenizers.
- `src/tools/injection.ts`: Rule-based prompt-injection, obfuscation, secret, and personal information (PII) detection.
- `src/tools/json-schema.ts`
- `src/tools/statistics.ts`
- `src/tools/tokenize.ts`
- `src/version.ts`

## Commands

| Command              | Purpose                                                                                               |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| `make help`          | Show this help                                                                                        |
| `make setup`         | Install locked dependencies                                                                           |
| `make build`         | Compile TypeScript to dist/                                                                           |
| `make lint`          | Lint with ESLint                                                                                      |
| `make typecheck`     | Type-check                                                                                            |
| `make test`          | Run the test suite                                                                                    |
| `make test-coverage` | Tests with the coverage gate used in CI                                                               |
| `make benchmark`     | Run the benchmark                                                                                     |
| `make all`           | Full local gate (mirror of continuous integration)                                                    |
| `make changelog`     | Regenerate CHANGELOG.md from Conventional Commits (git-cliff)                                         |
| `make cut-release`   | Cut a release locally: version bump, changelog, tag, GitHub release (RELEASE_VERSION=vX.Y.Z optional) |

Run the full local gate (`make all`) before committing; CI runs the same checks.

## Conventions

- Commits follow Conventional Commits (`feat:`, `fix:`, `perf:`, `refactor:`, `docs:`, `test:`, `ci:`, `chore:`).
  The changelog and the next version number are derived from them.
- Every number quoted in the README is produced by a command in this repository. When behavior
  changes, rerun that command and update the number in the same commit.
- When a component is added, removed or renamed, update `docs/architecture/architecture.mmd`
  and re-render `architecture.svg` so the diagram matches the code.
- README sections keep their fixed order. Prose avoids em and en dashes and promotional wording.
- Tests accompany behavior changes; a bug fix comes with a test that fails without it.
- Releases are cut with `make cut-release`.

## TypeScript notes

- Node and npm; `npm ci` installs the locked dependencies.
- ESLint and the TypeScript compiler run in strict mode; tests use Vitest.
- Inputs crossing a process boundary are validated with a schema before use.
